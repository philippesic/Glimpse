# Core implementation design

[Glimpse's product contract](../glimpse.md) governs the product. This revision replaces the egui/eframe and embedded AppKit application with GPUI 0.2.2. Linux is the current verification target; macOS compilation and interaction are unverified.

## Boundaries

The GPUI shell owns document IDs, tabs, focus, navigation history, search scope and user decisions. Disk files, save validation, recovery, search, directory enumeration, CLI parsing and lifecycle remain ordinary Rust modules. Worker completion uses a small renderer-independent callback, connected to a bounded GPUI wake channel. The domain modules are exposed through the library target and can be tested without opening a window. The runtime does not use egui. Retained egui presentation regression tests are test-only; they do not qualify the new interface.

Document reads use two bounded workers, mutations one, and maintenance one. Directory listings use two workers and stream bounded batches. Recursive search and syntax each use a latest-request mailbox. Relevant notifications trigger document validation; they are not authoritative versions. Wayland requests a frame when invalidation or a queued frame callback needs one, coalescing pending requests. The Wayland renderer creates its surface with the requested background and decoration mode from the beginning. Other platform backends retain their scheduling routes. No periodic scan or repaint loop is intended.

## Editor choice

The editor uses gpui-component 0.5.1 InputState in code-editor mode, retaining one entity per document. Its rope buffer, visible-line rendering, selection, clipboard, undo and GPUI input-method handling provide a smaller implementation surface than writing those primitives again. Composition retains the replaced text and selection until commit; cancellation restores them, and committed composition forms one Undo step. This is a provisional choice: a rope does not establish large-file performance, long-line responsiveness, IME correctness or accessibility.

The component is vendored under its Apache-2.0 license for externally supplied highlight spans, a steady caret, live indentation preferences, bounded visible-row shaping, and keyboard-operable menus. Line metadata retains lengths instead of individual rope copies. Initial file I/O can overlap native window creation. Large soft-wrapped documents prepare geometry on a worker in four-pixel width steps to reuse adjacent viewport layouts. Resizing keeps the current revision editable until the new layout is ready. The renderer uses a sparse row index and shapes only visible text. A line that needs one display row stores its length without allocating wrap ranges. The editor shares immutable rope revisions with syntax, automatic recovery, normal Save, the exact disk base and source accessibility. Long lines retain sparse wrapping checkpoints with consumed lookahead, candidate widths and indentation. Single-line edits resume before the edit and reuse an unchanged suffix only after exact mapped-state equality. Short lines have no checkpoint allocation. Equal-width ASCII words retain their specialized geometry path; unsupported edit shapes use full wrapping. Wrapped-row position lookup uses sorted byte ranges. Undo retains up to 32 MiB of edit data per input and keeps the newest group when it exceeds that budget. One previous geometry can be retained within a separate 4 MiB cache. Line/column uses rope character metrics, while newline counts update around each edit. Distant caret moves reveal their destination and refresh the newly visible rows. The existing bounded syntect/two-face worker remains responsible for syntax. When a large document enters Read, the worker releases unused grammar data and returns available heap pages. The editor keeps the installed spans. A later source request reloads grammar data when needed. Generation checks reject obsolete results; the worker supplies UTF-8 byte ranges directly. Externally highlighted inputs skip the component’s otherwise redundant synchronous parser. The xattr patch corrects the Linux errno name for aarch64 in GPUI's transitive archive dependency. These patches preserve file-save validation. Editor-owned context menus and Find panels retain weak parent references, so closing releases the editor and its text caches.

Cursor movement, selection and deletion use extended grapheme boundaries across rope chunks. Pointer and requested positions clamp to those boundaries; combining sequences and joined emoji remain one editing unit. Performance qualification must cover 10 MiB documents, long lines, graphemes, real IME composition and clipboard. None of those requirements is relaxed by choosing this component.

Linux Wayland forwards real keyboard events to the AT-SPI registry before dispatch and honors consumed events. Connection setup and reconnection run outside the interface thread; replies have a timeout, and inactive assistive access avoids the notification path. X11 retains its platform keyboard route. Native Orca checks exercise caret speech, editing, file navigation, Find, reading, native Save and decisions on both routes. Orca's keyboard commands on the Sway reference host work with the legacy AT-SPI device configuration. The default host key transport remains unqualified. These bounded workflows and an independent native key-consumption check do not qualify every screen-reader command or host configuration.

Accessibility text runs retain stable identities and shared properties across unchanged groups. Runs hold up to 2,048 selectable characters. Short source lines share a run with explicit internal line boundaries, and long lines use linked runs. Wider word offsets preserve navigation within longer runs. Identical blank lines share immutable properties. Metadata construction batches safe ASCII spans while preserving Unicode grapheme context and CRLF boundaries. The Linux AT-SPI adapter caches scalar offsets and compares edited leaf runs. Masked text, incomplete character metadata and hierarchy changes retain the complete traversal path. The consumer shares unchanged node pages across revisions and releases pages when their nodes disappear. A property-only update preserves existing child relationships.

Large source text updates prepare accessible runs directly from the editor revision on a background thread. Segmentation borrows contiguous lines and materializes only a line that spans rope chunks. The text node reports a busy state while the snapshot is pending and accepts assistive edits and selection actions once its text matches the buffer. The editor continues to accept keyboard input during preparation. Completed snapshots are checked against the current buffer and element identity before publication. An assistive text action reports success after the editor applies it to the current revision. A request that times out before application is cancelled.

## Reading pipeline

The Markdown worker receives an immutable editor revision and prepares the parser input off the UI thread. It converts pulldown-cmark events into native blocks, retaining nested styles, ordered-list starts, reference links, tables, task lists and literal HTML. Linkify identifies URL and email autolinks within ordinary text. Code and existing links keep their own semantics. Adjacent text shares one payload between image boundaries, with styles and links at their original offsets. Large documents pack completed blocks in bounded batches. The rendered spans and complete accessible Reading text share immutable chunks. Repeated line layouts share character and word-boundary data. Source remains authoritative. Image loading and link dispatch use document-relative resolution within the existing resource and scheme limits.

The parser benchmark builds the supported-size fixture and checks its block count and final heading:

```sh
cargo test --release --locked -p gpui-component benchmark_supported_markdown -- --ignored --nocapture --test-threads=1
```

Qualify this worker separately from native rendering, memory and assistive access.

## File safety and services

DiskFile retains observed identity, symlink binding and bytes. Save stages beside the target, preserves supported metadata, syncs, validates and atomically replaces. Hard links, unsupported ownership/metadata and changed destinations stop saving. Atomic replacement is not compare-and-swap against unrelated writers. External observation retains the existing binding when a symlink target changes, even when both targets have identical bytes; ordinary Save stays blocked until an explicit resolution.

Document observations check unchanged bytes in bounded chunks and reuse the saved snapshot. Changed files are read as new observations. At most two observation reads run at once. Repeated notifications coalesce into one follow-up per document, and a local edit during a read schedules a fresh observation without needing another filesystem event. Invalidated reads retain their slot until completion. A full read queue returns a typed deferral with a short retry. Watches include the chosen path, resolved target and pending observed target parents; rebinding refreshes them.

Content notifications affect matching documents; entry changes refresh the displayed folder. Unknown events, overflow and monitoring errors retain a full rescan. Registration is followed by validation, and Refresh Folder rearms monitoring after a directory is replaced. Watch directories resolve on the worker, share registrations across aliases and map events back to chosen paths. Monitoring failures remain in Warnings until acknowledged.

Failed opens retain the existing document and show a persistent, named explanation with details, retry and an explicit external-open action. Unsupported encodings, binary data and over-limit files never become editable buffers.

Save As rebinds after success; Save Copy retains the original binding. Existing destinations require a modal confirmation of an observed version. Destination identity checks run on the I/O path. Destinations already open in another tab must be closed first. A waiting CLI request requires explicit abandonment before Save As to another path; cancellation or failed saving keeps it waiting, while successful rebinding returns exit 1. Recovery remains mandatory for normal saves. A document’s recovery failure offers Retry, a new recovery copy elsewhere, and a separately confirmed one-attempt Save Without Recovery for an existing file without an unresolved conflict. The recovery-copy operation creates a new file exclusively, keeps the original association, and cannot replace an existing destination. Its output is itself the requested recovery copy. The one-attempt override bypasses neither disk validation nor metadata and replacement requirements.

Linux rename uses `renameat2(RENAME_NOREPLACE)` and Trash uses the trash crate's freedesktop implementation. Linux saving copies permissions and extended attributes; failures stop replacement. macOS retains `renamex_np`, NSFileManager Trash and `fcopyfile` metadata preservation behind platform configuration. Linux Reveal opens the containing directory with xdg-open. GPUI supplies native portal file dialogs.

A launch with no arguments starts navigation at Home and automatically claims available abandoned drafts into the new locked session before reporting readiness. Explicit path, open and picker launches leave unrelated drafts available in Recovery. Restoration runs one draft at a time, retains the original binding/base, and reports unreadable or truncated inventory rather than declaring successful recovery. Active sessions, failed-save candidates and resolved history are excluded from automatic restoration.

Recovery keeps private, locked session records with exact local text and observed disk bytes. Recovery lists storage usage, abandoned drafts, failed-save candidates and resolved history, with keyboard-accessible restoration and Trash controls. Claiming an abandoned draft retains its binding; history and observed snapshots open separate copies. Restoring an already-open original also creates a separate copy. New save candidates identify their owning document, so resolving one document archives only its candidates through the acknowledged generation. Legacy candidates without ownership remain available for explicit management. Closing waits for acknowledgment that the exact recovery generation was resolved. Cleanup failure keeps the document open with Retry and Keep Open actions; Keep Open creates a newer recovery generation. Close decisions retain the named document IDs across tab switches, and Save and Close saves those documents before cleanup. Edits during cleanup cancel that document’s close.

Clean external refresh replaces only the changed grapheme range, preserves selection in unchanged text, and isolates the old text as one Undo step. Pointer selection, held Shift selection and IME composition defer installation. Read-only picker previews accept verified programmatic refresh while refusing user edits. Passive refresh does not promote a preview tab. The status footer reserves a second line for warnings and messages in taller narrow windows.

Conflict decisions capture the document, local generation and specific observed disk version. Compare exposes selectable, read-only local and disk text. Reload revalidates the observed version and acknowledges recovery cleanup before replacing the buffer; the old local text remains in Undo and history. Overwrite uses the normal validated-save path against the explicitly observed version. Both operations retain local text on failure.

Requested CLI files complete only after destination validation and recovery cleanup. Clean close can complete a request; closing one of several requested files leaves the others waiting. Dirty Finish offers Save, Discard and Cancel. Save alone keeps waiting; Discard or Reload that abandons requested local edits returns failure. Generation checks, exact disk bases and authoritative buffer comparisons reject obsolete completion and cleanup replies.

Ordinary desktop Open and Save share the exact editor revision with the retained disk base. Disk comparisons and writes stream its bytes, including an original BOM. Recovery streams the local text and disk base into a private temporary JSON file, then flushes and syncs before replacement. The stored format remains compatible. A completed save updates newer automatic recovery to the saved disk base before acknowledgment. Save As also transfers the newer draft’s destination. Late updates made against the preceding binding are translated only through the UI’s adoption generation; later observations retain their own bases. Recovery writes and rebinding serialize on a worker-only lock, while the UI’s acknowledgment touches only brief metadata locks.

The GPUI accessibility layer associates semantics and UI-thread actions with painted elements, including cached drawing. Linux uses the AccessKit AT-SPI adapter. AccessKit 0.25.2 is vendored with shared node properties that copy on mutation; this avoids duplicating immutable text during tree updates while preserving independent setters and the serialized representation. Text identifiers use compact parent/child keys, and hidden documents release accessibility caches that must be rebuilt on return. Buttons expose labels, selection, availability and focus; source inputs expose text runs, line and word boundaries, caret, selection and supported editing actions. Text metadata stores compact byte lengths and streams word boundaries rather than retaining a machine-sized offset for every character. Edits re-segment affected hard lines while unchanged text runs retain their identities and shared data. The adapter publishes changed runs and restores complete groups when they return to the active tree. Complete text and selection remain exposed. Dialogs restrict that tree and reject requests targeting hidden background controls. Activating assistive access requests a fresh frame. Menus and directory rows expose named actions, selection and keyboard focus; document tabs and Preferences fields expose their roles and names. Rendered reading blocks expose read-only text, heading levels, image descriptions, task states and table structure. Reading focus waits until parsed content has painted and does not displace a subsequent focus choice. A Links menu provides keyboard access through the same safe document-relative routing as pointer activation. The Reading view shares immutable text chunks between rendered spans and a complete read-only text range. Paragraph boundaries and Unicode offsets stay stable as the visible blocks change. The Linux adapter tracks document text independently of painted structure, so scrolling does not generate text edits. Unmeasured list rows share their index storage. Native Linux Wayland Orca checks use the default keyboard configuration with `DISPLAY` unset. They cover keyboard path entry, source editing, Find, Save and uninterrupted Markdown speech through an offscreen heading. A separate supported-size check verifies preparation and sentence ranges at both ends. Supported-size performance and macOS accessibility require their own evidence.

GPUI is vendored at 0.2.2. Its Linux X11 loop drains buffered events after dispatch so mapping events cannot leave a window waiting indefinitely for a readable socket. Its Linux Wayland startup fix handles keyboard initialization: modifier masks received before a keymap are deferred until it arrives, and untranslatable key events are ignored safely. The other upstream platform implementations remain unchanged by this patch. Shared text layout also keys cached measurements by truncation width and preserves the original style runs across measurement passes, so constrained labels can produce an ellipsis. macOS compilation and interaction remain unqualified.

Save, Reload and file-access failures persist with the affected document and retain the appropriate retry action. Failed destination saves retain their path and operation. Native chooser errors are distinct from cancellation, and their retry retains Save As or Save Copy. Recovery maintenance warnings remain separately visible until acknowledged; later success or background updates cannot hide them. Warning details retain 32 distinct messages and disclose omitted earlier notices.

New-file saves retain the staged file’s identity, resolved destination and exact candidate bytes. Before adopting the file, the worker verifies that the chosen path still names that created version. A post-creation replacement or symlink retarget stops adoption.

## Preferences and layout

Preferences edits a draft until Apply validates and persists it. The worker acknowledges settings writes before the shell adopts the saved values. Cancel retains the running configuration; Reload reads the observed file again. External settings changes block replacement, and each write validates the candidate’s observed bytes rather than a mutable worker-wide baseline. The writer enforces the same 64 KiB limit as the reader. Theme, typography, wrapping, indentation, line numbers, current-line highlighting, syntax, density, hidden files, search filters and shortcut overrides share the stored configuration.

Locations contains explicit pins, frequent/recent folders and mounted locations. Successful document openings update visit ranking; traversal alone does not. The shell allows one settings write at a time and stages visits while Preferences is open. Pin changes become live only after acknowledgment. Mount discovery uses cached OS mount tables without probing the listed paths. Selecting a location starts its filesystem work explicitly. Linux reads the [kernel mount table](https://www.kernel.org/doc/Documentation/filesystems/proc.txt), preserves native path bytes and reports bounded-list truncation. macOS uses a non-blocking mount-table snapshot and filters it to `/Volumes`; that implementation is unqualified.

Shell buttons and document tabs use focusable GPUI controls. Navigator selection has a persistent geometric marker, and keyboard focus has a separate outline. File and folder chooser commands request their respective destination types. Preferences contains Tab navigation, scrolls focused fields into view and restores focus on dismissal. The navigator divider accepts pointer dragging and keyboard resizing. Narrow layouts show either navigator or document, use fewer visible toolbar actions and retain the command palette. The width threshold accounts for interface scale. Short windows keep the Find query and match controls visible and tighten vertical spacing to preserve editor rows. Menus support keyboard opening, focus return and scrolling; labels use bounded ellipses and wrapped tooltips. Duplicate document names use the shortest distinguishing parent suffix, with full paths available on hover. Document subscriptions end when their tabs close. App shortcut matching precedes editor bindings while preserving reserved editing keys. These changes do not establish screen-reader support.

The window title identifies the active document and modification state; the footer retains line/column, UTF-8/BOM and current newline information. Active tabs use the primary selected treatment. The path bar exposes ancestor buttons and inline entry; opening Location selects its path for replacement. Tab and Shift-Tab cycle worker-produced completions; escaped entries retain native filename bytes. Completion lists disclose truncation. Copy Path uses the same lossless entry representation: ordinary paths remain text, control characters use quoted strings, absolute paths with invalid UTF-8 use local file URLs, and relative byte paths use escaped byte literals. Location decodes those forms and rejects malformed escapes and NUL bytes. File and folder drops use the same asynchronous open path without changing pinned scope. Predominantly horizontal navigator scrolling emits at most one history step per touch sequence or wheel burst; vertical and strongly diagonal scrolling stays in the list. Back/Forward mouse buttons use the same history commands.

Open requests retain the user interaction generation that issued them. A late explicit file open becomes a background tab after the user moves on; a stale preview is discarded. Cursor positioning for a background document does not focus it. A requested CLI file that becomes a directory during startup fails the request rather than reporting successful readiness.

Directory refresh retains the current rows until the replacement listing completes. A returning location waits for its complete listing before reusing the saved scroll handle, so empty or partial frames cannot reset its position. Initial visits still stream batches. The shell sorts once per drained batch group and caches visible indices over shared immutable entries. Hidden-file decisions inspect native names before display escaping.

Loading, slow reads, empty folders, filtering and unavailable or partial listings remain visible in the navigator. Error details expose the full path, failure and Retry. Stop Reading rejects late results and stays paused through filesystem notifications until explicit refresh or navigation; document-change checks continue. Obsolete directory requests are cancelled when Location changes. Two directory workers coalesce requests by logical path; repeated refreshes retain only the newest generation and cannot occupy both workers with the same path. Cancellation rejects results even while a filesystem call remains blocked. Two distinct stalled reads can occupy both workers until they return; editing, saving and Stop Reading remain independent of directory enumeration. A full directory queue is an explicit failure rather than indefinite startup waiting.

Document Find scans immutable text snapshots off the UI thread. Each panel keeps one running scan and one replaceable pending request. Query changes, edits and dismissal cancel obsolete work; pending results cannot enable replacement against an older buffer. Only visible matches are laid out. Replace All streams the unmatched source chunks into its candidate on a worker and applies one undoable change after checking that the source and request remain current. Match counts are exposed as accessible text. Supported-size responsiveness and assistive resource use still require qualification.

Recursive search has its own persistent state, result selection and coverage surface. Effective scope is the temporary Search This Folder override, then the pin, then Location. Navigation changes only an unpinned, non-temporary scope; a changed effective target cancels old work. Closing search retires the temporary override and leaves the pin intact. The command palette preserves the search query and target while it is open.

Filename indexing is explicit and session-only. Index, Rebuild and Remove controls show snapshot size, staleness and filter incompatibility. Compatible indexed queries update while typed; empty ordinary queries do not build an index. Result rows are virtualized, expose full paths in tooltips, emphasize matches and support arrow, page, Home/End and Enter navigation. Text excerpts retain bounded context around a match. Filename results focus an existing document without moving its caret. Saved-text results position the caret at the matching line; activation rechecks the observed bytes and refuses to jump into a dirty open document. Such failures remain with the results rather than only in the global status line. Picker result selection is independent of a previous navigator selection and is returned only by Choose.

Search excludes symlink entries, metadata unless enabled, configured ignore patterns and nested mounts. Linux reads the mount table and checks bind mounts as well as device changes. macOS has a bounded, non-blocking mount-table implementation in its platform module; its compilation and behavior are unqualified. Linux tests create bind mounts only in private user/mount namespaces, and native checks cover both excluded traversal and explicit navigation into a mounted search root.

## Presentation gaps and qualification

The product contract and native Linux evaluation determine qualification. The following remain incomplete:

- Complete contextual command availability. macOS system-menu integration remains unverified.
- Complete search adaptation at narrow widths and large interface scales, including the full coverage and permission-failure matrix.
- Supported-size Markdown responsiveness and complete dialect, link, overflow and assistive-access qualification. The native read view now parses off-thread, virtualizes blocks, retains source position, renders bounded local rasters, omits remote images, displays raw HTML and routes relative links from the document folder.
- Complete supported-size performance, spoken navigation/editing, keyboard and size/theme/settings matrices, additional international-input cases and macOS behavior. Native Linux IBus/libpinyin checks cover preedit, commit, cancellation, selection replacement, Undo and external-refresh deferral; these do not qualify every input method or platform. Modal behavior across asynchronous completions still requires qualification.

The new view virtualizes directory rows and stores per-folder selection and scroll state. Syntax work remains bounded; full-wrap fallbacks and transient persistence memory still require supported-size performance qualification. On GNU/Linux, the process configures glibc mapping and trimming thresholds unless allocator environment settings are supplied. Preparing a large reading view releases temporary pages on the read worker before publication. Leaving reading mode releases its source and image cache. Retiring a large view schedules background page reclamation after its rendered frames are released. Pending reclamation tasks are replaced rather than accumulated. This does not establish a total-memory bound; supported-size source and reading workloads still exceed the memory target. Other platforms retain their allocation policy. Linux native checks qualify only their executed scenarios. Whole-app performance, safety and accessibility require current-build evidence for the complete acceptance matrix.

`GLIMPSE_TIMING=1` emits an editable-frame checkpoint from the first callback after the ready view was drawn. Process-to-checkpoint time is an upper bound on that rendered, input-ready state; it includes callback scheduling and is not physical presentation. The existing lifecycle readiness message remains a later, separate boundary.
