# Glimpse

- Follow [glimpse.md](glimpse.md) for product scope and design. Use a native Rust GUI and renderer; Tauri, Electron, and WebView application frontends/renderers are excluded. Verify desktop interactions in the actual native application.
- For UI/UX improvement work, follow [native evaluation](docs/native-evaluation.md): repeatable computer-use tasks, assigned Mac references, separate quality gates and direct evidence-based verification. The guide does not authorize starting or resuming an unattended campaign.
- Run Git operations from Glimpse's own repository root. Keep commits coherent and subjects short, with no coauthor trailers. Integrate changes through a PR, including changes that will merge immediately; do not bypass the PR record with direct changes to remote `main`. Push only when requested. A PR requirement does not independently authorize a push or remote creation.
- Treat all published text as part of the product: documentation, Markdown, comments, snippets, string literals, commit messages, PR text, and release notes. Keep it accurate, concise, intentional, and useful to its reader. Remove conversational filler, model/debate transcripts, tool output, progress narration, stale plans, unexplained fragments, and unverified claims before publication. Comments should explain a reason or invariant rather than narrate obvious code.
- Keep private working notes, drafts, checkpoints, raw logs, and disposable experiments under ignored `.local/` or outside the repository. Promote only edited, durable material into project documentation. Keep the requested design document and useful contributor documentation tracked; do not blanket-ignore Markdown or comments.
- Maintain `.gitignore` as build and tooling artifacts appear. Commit source, manifests, the application lockfile, small intentional fixtures, and useful project documentation. Exclude build products, caches, credentials, recovery data, downloads, and large generated artifacts.
- Before committing and before each authorized push, inspect the complete relevant diff and new files for publication quality, including prose and incidental text. Clean private drafts from unpublished history before pushing; deleting them only in a later commit still publishes them. Ignore rules and automated checks do not replace this review. Do not rewrite already-published history without explicit authorization.
